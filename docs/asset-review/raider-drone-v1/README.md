# Raider drone — native sprite handoff

This is the **moss-covered drone with the yellow cross and hanging claw** selected by the user, extracted from `raider_drone_boss_sprite_sheet.png`. It is not a new boss design or the later four-boss presentation board.

## Files

- **idle.png**, **move.png**, **theft.png**, **damage.png**: four 8-frame sheets containing all 32 isolated source poses.
- **theft-airframe.png**: the eight theft poses with the green hanging payload separated in poses 18–23. Use this when carrying an actual game plant.
- **theft-payload-fx.png**: removed plant fragments and three motion streaks, in matching cells. Overlaying this on theft-airframe.png reconstructs theft.png exactly. Other smoke/spark damage effects remain in their original poses. No hidden gripper surfaces were invented.
- **atlas.json**: frame rectangles, fixed anchor, claw sockets, trimmed offsets, eight animation clips, palette and extraction provenance. Compatible with the existing `assets/native-atlas.mjs`.
- **export_frames.py**: validates the sheets, then exports every individual PNG, tight transparent crop and animation strip. The downloadable ZIP already contains those exports.
- **validation.json**: pixel checks and file hashes.

## Native size — do not scale individual sprites

The four primary sheets and two optional layers are **512×64 px: 8 columns × 1 row, with 64×64 transparent cells**. Column c starts at `x=c*64`, `y=0`. The ZIP also includes the combined **512×256 px** master, regenerated by the export script. No grid lines, text or background are baked into these files.

The idle drone's visible bounds are **39×28 px**, beside the original **24-pixel-tall Max**. All poses use the same **5:1 reduction** from the supplied master. Different body angles keep their natural width; frames were not independently stretched to a bounding box. There are **32 distinct source poses**, not 64 fabricated animation frames.

Core/hover anchor: **(32,32)** in every cell. Alpha is strictly 0 or 255. The 20 opaque colours are sampled from the original/native reference artwork. Draw one PNG pixel to one game-canvas pixel; let the game enlarge the whole canvas. Use integer placement and nearest-neighbour filtering. Use the supplied crop offset/anchor when drawing a tight crop; never re-centre it.

Death is a smoke/tilt one-shot, not a fully vanished corpse. Remove its visual after the clip; do not loop into recovery. Animation timing is a handoff default, not a new gameplay damage schedule.

## Existing Canvas adapter

```js
import {loadAtlas, drawAtlas} from './assets/native-atlas.mjs';
const atlas = await loadAtlas('docs/asset-review/raider-drone-v1/atlas.json');
const clean = {...atlas, images: {...atlas.images, drone2: atlas.images.airframe}};
const frame = drawAtlas(ctx, clean, 'carry', stateSeconds, screenX, screenY, {facing});
const [sx, sy] = frame.sockets.claw;
const gripX = Math.round(screenX) + (facing < 0 ? -1 : 1) * (sx - 32);
const gripY = Math.round(screenY) + sy - 32;
// Draw the stolen plant's own native pixels behind the claw at gripX/gripY.
```

Load once, not inside the render loop. `screenX/screenY` are native canvas coordinates after camera subtraction. The socket marks the gap between the claw fingers; it is not the ground. Physics bounds must follow the hull, not the 64×64 transparent cell.

## Main-developer integration boundary

This commit is **art and handoff only**. Nothing is imported into gameplay or added to the production build. Do not replace the existing Hollow Crown, companion, skins, saves, audio or run-bouquet renderer. Level 10 is a proposed slot for this drone, not an implemented or user-finalised assignment.

When integrating, keep the real stolen plant ID/state, host-authoritative co-op damage and theft, and the current timer-driven attack tells.
